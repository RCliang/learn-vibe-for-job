01 · 心智转变

AI 是副驾，你是驾驶员

❌ Vibe Coding 的陷阱

让 AI 全权代写，自己只负责说「好」。

结果：项目跑起来了，但你说不清代码在干嘛；面试一问就露底；入职第一天要在别人的代码上改功能，你改不动。

✅ 本课程要的姿态

AI 负责打字，你负责判断。

你提需求、你读代码、你决定改哪里、你验收结果——重活交出去，方向盘握在自己手里。

铁律
AI 生成的每一行代码，你都要能说清它在干嘛。
说不清的，要么问懂，要么删掉重来。
01 · 五步工作流

工作流是一个循环，不是「许愿一次拿成品」

① 提需求四要素说清楚→ ② AI 生成拿到代码→ ③ 读懂能解释每行→ ④ 修改能动手改→ ⑤ 运行验证对照验收标准→ 交付满意了才算完
↩ 报错 / 不满意 → 修 bug、再提需求，回到第 ① 步。一个需求来回三五轮，是常态，不是你不行。

「读懂」和「修改」是两个独立环节：读懂 = 能解释，修改 = 能动手改。看懂了不代表改得动。本章就是把这五步各自练一遍。

01 · 读懂代码

每次拿到 AI 的代码，先问三个问题

1

这个文件整体在干什么？

必须能用一句话说清。例：「把流水账文本发给大模型，把结果存成 md 文件」

2

每个函数 / 代码块在干什么？

输入是什么、输出是什么、谁调用它——三件事说全，这个函数就算读懂了

3

我改哪里会改变什么？

找到那个「拧一下就有效果」的旋钮：比如 prompt 文本、模型名、输出文件名

三问答不上来的部分，就是你要追问 AI 的部分：「解释第 X 行到第 Y 行在做什么，为什么要这样写」

01 · 读懂代码

AI 出题考核：验证你是真读懂了「我大概看懂了」是最容易骗自己的一句话——用考核闭环堵住它

AI 生成代码后，把这段指令发给它：

你刚为我生成了这段代码。现在请你扮演严格的代码面试官， 针对这段代码出 3 道阅读理解题，考察我是否真的读懂了： 第 1 题问「这段代码整体在做什么」； 第 2 题问某个具体行为（如某个参数、某行的作用）； 第 3 题问「如果我改动某个地方，会发生什么」。 一次只出一道，等我回答后你先批改，再出下一道。 最后告诉我：3 题里答对了几题，哪部分理解有偏差。

及格线：3 题答对 2 题

答错的题让 AI 讲解后，重新出一道同类题再答一遍，答对才继续往下走。

为什么这招有效

向 AI 提问是输入，被考核是输出——只有输出才能暴露真实的理解缺口。

这个习惯保持到课程结束，你读代码的能力会以每周可见的速度增长。

02

指令四要素

同一个需求，指令质量决定你是一轮拿到能用的代码，
还是跟 AI 来回拉扯十轮，最后自己重写。

02 · 指令四要素

差指令 vs 好指令

❌ 差指令（AI 只能瞎猜）

「帮我写个周报工具」

AI 不知道：
· 用什么语言？
· 输入从哪来？
· 调哪个模型？
· 输出成什么样？

于是它自由发挥，你拿到的东西和你的环境对不上。

✅ 好指令（四要素齐全）

【任务】写一个 Python 脚本 weekly_report.py，把我的流水账整理成结构化周报

【上下文】流水账写在脚本顶部的 RAW_TEXT 变量里；用 openai SDK 调 DeepSeek，Key 和 base_url 从 .env 读；模型用 deepseek-chat

【约束】单文件、不超过 80 行；prompt 里要求按「本周完成 / 进行中 / 下周计划 / 需要支持」四节输出 Markdown

【验收】运行 python weekly_report.py 后当前目录生成 weekly_report.md，四节齐全、每条动词开头，我能直接提交给领导

02 · 指令四要素

四要素速查表缺一个，AI 就多猜一次；猜错一次，你就多返工一轮

要素回答的问题缺了会怎样
任务做什么、产出是什么文件AI 自由发挥，返工
上下文输入从哪来、用什么库、环境如何生成的代码和你的环境对不上
约束语言 / 框架 / 格式 / 长度边界用了你还没学的东西，看不懂
验收标准怎么证明做好了你自己都不知道算不算完成

🔗 与 Ch2 的关系

把【任务】换成任意业务、【约束】里加上「输出 JSON 格式」，就是 Ch2 的 Prompt Engineering。本章只需要在给编程助手提需求时把它用熟。

03 · 实战 · STEP 3

Step 3：多轮修改（真正开始 vibe）真实需求从来一轮做不完——依次提这三个，体验「修改」环节

① 改输出

「周报每节最多 5 条，多余的合并；语气正式但不僵硬」

练的是：把审美要求说成可执行的约束

② 改健壮性

「如果 API 调用失败，给出人类能看懂的提示，告诉我去查 .env」

想想 Ch0 的 401——报错要说人话

③ 加功能

「在周报末尾追加一节『本周关键词』，让模型从流水账里提炼 3 个词」

练的是：在已有代码上长出新功能

每轮修改后都要重跑验证——这就是「验收标准」的日常用法。改完不跑，等于没改。

04

调试基本功：报错不可怕

报错不是失败，是 Python 在精确地告诉你哪里出了问题。
这一部分只练一件事：从下往上读 traceback 的肌肉记忆。

04 · 调试基本功

traceback 解剖读法只有一句：从最后一行开始往上读

从下往上
Traceback (most recent call last): ← 固定开头，不用管 File "weekly_report.py", line 25, in <module> main() ┐ File "weekly_report.py", line 21, in main │ 调用路径：谁调用了谁 report = generate_weekly_report(RAW_TEXT) ┘ （先跳过） File "weekly_report.py", line 12, in generate_weekly_report ← 出错的位置 return response.choices[0].message.content ← 出错的那一行 NameError: name 'response' is not defined ← ★ 错误类型 + 原因

三步读法

① 最后一行 → 什么错
② 带行号的行 → 在哪错
③ 再往上 → 怎么走到这的

够用的结论

零基础 90% 的报错，只看最后一行 + 出错行就能定位。中间那串调用路径，等你熟练了再看。

04 · 调试基本功

贴报错给 AI 的正确姿势AI 修 bug 的效果，取决于你给了它多少信息

我运行 weekly_report.py 报了下面的错 （完整复制，包括最后的错误类型行）： 【粘贴完整 traceback】 我期望：运行后生成 weekly_report.md 实际：直接报错退出了 已经试过：检查过第 12 行附近，没看出问题 请先告诉我原因是什么，再告诉我具体改哪几行。
🚫 三条红线

① traceback 要完整——文字比截图好
② 期望 vs 实际都说清
③ 先要解释，再要改法——不然下次你还是不会

对话越聊越乱？

AI 记错前文、上下文被历史污染 → 敲 /clear 清空重开，把关键信息重新贴一遍。

04 · 调试基本功 · 必做

3 段预置 bug 修复实战code/ch1-vibe-workflow/bugs/ —— 每段都走这六步，不许直接问 AI 答案

① 运行让它报错→ ② 从下往上读说出错误类型→ ③ 说出猜测先自己想→ ④ 贴给 AI验证猜测→ ⑤ 修复动手改→ ⑥ 再运行验证通过
文件你会遇到的报错训练点
bug1_name_error.pyNameError变量名拼写：traceback 最后一行直指答案
bug2_indent_error.pyIndentationErrorPython 用缩进表示层级，多一层少一层都不行
bug3_api_401.py401 鉴权失败不是代码错，是环境错：Key 没读到 / 写错 → 回忆 Ch0 的 .env

bug3 特别重要：它教会你「报错不一定是代码问题」。修法提示——从 .env 正确读取 Key，答案就藏在 Ch0 的 hello_llm.py 里。

📓 给自己建一本错题本：每修完一个报错记一行 报错类型 → 原因 → 解法。四周后它就是你的私人排错手册，也是面试讲「踩坑经验」的素材。
