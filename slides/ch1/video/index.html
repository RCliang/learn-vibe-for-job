心智转变与五步工作流

PART 01 · 心智转变

AI 是副驾，你是驾驶员

陷阱：全权代写，你只说「好」

项目跑起来了，表现和期待天差地别，
而且 review 不动、不知道哪块代码管哪块功能

铁律（全课程适用）

AI 生成的代码，你要能说清它在干嘛。
说不清的：要么问懂，要么删掉重来

PART 01 · 五步工作流

是个循环，不是流水线

提需求→ AI 生成→ 读懂→ 修改→ 运行验证→ 交付
报错 / 不满意 → 回到「提需求」
「读懂」和「修改」是两种能力——看懂了 ≠ 改得动；循环转三五轮是常态，别因此觉得自己不行
PART 01 · 读懂代码

三问法

1
这个文件整体在干什么？标准：一句话说清
2
每个函数在干什么？输入是什么 · 输出是什么 · 谁调用它
3
我改哪里会改变什么？找「拧一下就有效果」的旋钮：prompt、模型名、输出文件名
问法模板：「解释第 X 行到第 Y 行在做什么，为什么要这样写」 #「为什么」比「是什么」值钱
PART 01 · AI 出题考核

让 AI 出题，考你自己

怎么考

让 AI 当严格面试官，出三道阅读理解：
整体在做什么 / 某个行为 / 改某处会怎样
一次一道，先批改再出下一道

及格线 · 三道对两道

答错的让它讲解，
再出一道同类题重答

提问是输入，被考核是输出——只有输出才能暴露真实的理解缺口 · 做完考核，弹幕扣个 1
02
指令四要素
跟 AI 协作，写指令的能力比写代码的能力更稀缺——
同一个需求，指令质量决定一轮拿到，还是拉扯十轮
PART 02 · 差指令 vs 好指令

四个要素，一次说清

$ 帮我写个周报工具 # AI 只能瞎猜： ? 什么语言 ? 输入从哪来 ? 调哪个模型 ? 输出成什么样

四要素齐全

【任务】做什么、产出什么文件
【上下文】输入、SDK、.env、模型名
【约束】单文件、不超过 80 行、四节 Markdown
【验收】生成 weekly_report.md，四节齐全、动词开头

把【验收】写清楚，AI 自己都会往这个标准上凑
PART 02 · 速查表

每个要素都在回答一个问题

任
做什么、产出什么文件缺了：AI 自由发挥，你返工
境
输入从哪来、用什么库、环境如何缺了：代码跟你的环境对不上——新手最常撞的墙
界
语言、框架、格式、长度边界缺了：它会用你还没学的东西，你看不懂
收
怎么证明做好了缺了最惨：你自己都不知道算不算完成
把【任务】换成任意业务、【约束】加上「输出 JSON」——就是 Ch2 的 Prompt Engineering

04
调试基本功
报错不是失败，是 Python 在精确地告诉你哪里出了问题——
连文件名、行号、原因都替你打印好了；只练一件事：从下往上读
PART 04 · TRACEBACK 解剖

从下往上读

Traceback (most recent call last): File "utils.py", line 3 from report import * File "weekly_report.py", line 12 print(response.text) NameError: name 'response' is not defined # ↑ 最后一行：什么错（先看这） # ↑ 带行号的：在哪错 # ↑ 再往上：怎么走到这的

三步读法

① 最后一行 → 什么错
② 带行号那行 → 在哪错
③ 再往上 → 调用路径

零基础阶段，90% 的报错只看这两处就能定位

PART 04 · 贴报错给 AI

正确姿势：四段 + 一句

模板

① 完整 traceback（复制文字，别截图）　② 我期望什么　③ 实际发生了什么　④ 我已经试过什么
最后加一句：请先告诉我原因，再告诉我具体改哪几行

只贴报错不说期望，AI 只能猜；只要改法不要解释，下次同样的错你还是不会 · 对话越聊越乱？敲 /clear 重开，比在乱局里纠缠快得多
PART 04 · 修复实战

三段预置 bug，必修

运行→ 从下往上读→ 先猜→ 贴给 AI 验证→ 修复→ 再运行

bug1 · NameError

变量名拼写，最后一行直指答案

bug2 · IndentationError

缩进即层级，多一层少一层都不行

bug3 · API 401

报错不一定是代码问题——是 Key 没读到，环境问题

先自己猜，再问 AI——跳过猜测，练习就废了 · 每修完一个，往错题本记一行：报错 → 原因 → 解法
